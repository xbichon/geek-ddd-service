# 目录结构规范

## 2.目录命名规范

### （1）业务领域模块 (context.*)
- 命名格式：`context.{业务领域}`
- 示例：`context.education`, `context.manager`, `context.security`
- 每个业务领域模块代表一个限界上下文

### （2）分层目录
1. **adapter** - 适配器层，对外部系统的适配
2. **application** - 应用层，协调领域对象完成业务逻辑
3. **domain** - 领域层，核心业务逻辑

### （3）应用层子目录
1. **command** - 命令处理（写操作）
2. **query** - 查询处理（读操作）
3. **initialize** - 初始化相关

### （4）领域层子目录
1. **model** - 领域模型
2. **repository** - 领域仓储接口
3. **service** - 领域服务
4. **event** - 领域事件
5. **value** - 值对象
6. **exception** - 领域异常

### （5）数据库迁移脚本目录
- instructions/src/main/resources/database/migrations/** - 数据库迁移脚本，包含主迁移脚本和各业务领域的迁移脚本
   - **master.xml** - 主迁移脚本
   - **{业务领域}/** - 业务领域数据库资源目录
      - **{版本号}.xml** - 具体的数据库迁移脚本

## 3. 文件命名规范

### (1) Java 类命名
- **Command DTO**: `{动名词}Command.java` (如: `CreateStudentCommand.java`)
- **Command Handler**: `{动名词}CommandHandler.java` (如: `CreateStudentCommandHandler.java`)
- **Controller**: `{业务名}Controller.java` (如: `StudentController.java`)
- **Repository**: `{业务名}Repository.java` (如: `StudentRepository.java`)
- **Domain Model**: `{业务名}.java` (如: `Student.java`)
- **Service**: `{业务名}{动作}Service.java` (如: `StudentCreationService.java`)

### (2) 配置文件命名
- **数据库迁移脚本**: `{模块名}.xml` (如: `student.xml`)
- **JOOQ 配置**: `jooq-config.xml`
- **Liquibase 配置**: `liquibase-config.xml`

## 4. 应用要求
### （1）设计原则
1. **分层架构** - 严格遵循 DDD 分层架构模式
2. **领域驱动** - 业务逻辑集中在领域层
3. **单一职责** - 每个类和模块只负责特定的功能
4. **可扩展性** - 通过模块化设计支持功能扩展
5. **一致性** - 统一的命名规范和目录结构

### （2）目录创建
- 严格按照目录命名规范创建对应的目录结构

## 5. 执行规范

### （1）规范优先级
1. 当创建模块、目录或文件时，必须遵循以下优先级：
   - **本规范文档**（最高优先级，必须严格遵守）
   - 用户具体需求 
2. 以下禁止作为参考
   - 现有项目的目录结构
   - AI 固有经验

### （2）执行步骤

1. 第1步：规划目录结构（必须执行）
   - 在创建任何文件前，先根据本规范规划完整的目录树
   - **不要**参考现有项目的目录结构（即使现有项目结构可能与规范不符）
   - 每一个目录的创建都必须有规范依据
2. 第2步：执行创建
   - 严格按照规划的目录结构创建文件
   - 文件命名必须完全符合本规范要求
   - 如需参考现有代码，仅限参考**代码风格**（如注解使用、Lombok 用法等），绝不能参考目录组织方式
3. 第3步：验证检查（必须执行）
   - 创建完成后，逐条对照本规范验证：
     * 目录层级是否正确
     * 文件命名是否符合规范
     * 放置位置是否符合各层职责
   - 如发现不符合规范的，立即修正

### （3）特殊情况处理
- 如果发现现有项目结构与本规范不一致，**以本规范为准**
- 如果发现本规范存在歧义或冲突，先询问用户，不要自行决定

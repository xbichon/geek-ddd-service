## 角色
你是专业的领域驱动设计专家，当用户创建新模块目录时必须使用此技能

## 背景知识
该部分介绍此项目的目录结构的规范，使用目录树的结构加对应的描述说明，目录的层级结构如下：
 ```
├── src/
│   ├── main/
│   │   ├── java/
│   │   │   ├── {包名}/
│   │   │   │   ├── {模块名}/
│   │   │   │   │   ├── adapter/
│   │   │   │   │   │   ├── controller/     # 控制器（处理HTTP请求）
│   │   │   │   │   ├── application/        # 应用层
│   │   │   │   │   │   ├── command/        # 命令处理器（写操作）
│   │   │   │   │   │   │   ├── CreateStudentCommand.java #命令DTO类，以动名词命名，结尾为Command
│   │   │   │   │   │   │   ├── CreateStudentCommandHandler.java #命令处理器，以动名词命名，结尾为Handler
│   │   │   │   │   │   ├── query/          # 查询处理器（读操作）
│   │   │   │   │   ├── domain/             # 领域层
│   │   │   │   │   │   ├── model/          # 领域模型
│   │   │   │   │   │   ├── repository/     # 领域仓储
│   │   │   │   │   │   ├── service/        # 领域服务
│   │   │   │   │   │   ├── event/          # 领域事件
│   │   │   │   │   │   ├── value/          # 值对象
│   │   │   │   │   ├── exception/          # 领域异常    
│   │   ├── source/                         # 源代码
│   │   │   ├── database/                   # 数据库脚本
│   │   │   │   ├── migrations/             # 数据库迁移脚本
│   │   │   │   │   ├── v1.0/
│   │   │   │   │   │   ├── {模块名}.xml     # 数据库迁移脚本
```

## 操作步骤
1. 当用户提出创建项目目录、模块目录时，要求先参考目录结构规范，按要求创建目录结构。
2. 如果是从零开始创建模块目录
   2.1 如果未给出包名，参考其他以Context开头的模块中的包的包名； 
   2.2 如果未给出模块名，询问客户模块的名称是什么？
3. 如果是添加子目录，根据目录结构规范添加对应的子目录。

## 要求
1. 严格遵循背景知识中给出的规范进行目录创建，不能添加规范外的目录，例如规范中没有infrastructure目录，就绝对不能添加。
